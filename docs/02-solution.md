# 方案

## 为什么这样做

企业制度问答最关键的错误，是拿到一条看似正确的规定后就忽略其他可能适用的材料。我们因此将“寻找证据”和“给出结论”分别建模。工具提供可追溯的原文及相关候选，模型解释它们的含义、条件与关系。

选择原生 Python 循环，是因为本项目只需要少量动作、一个状态对象和明确的退出条件。这样便于核对每轮输入、工具结果和下一步，也便于把问答服务与可选 embedding 服务独立替换。

关键词是低依赖的默认入口，能直接匹配文档编号和制度术语。不同措辞通过模型改写、双语查询及可选向量补充召回。模型权重和服务都由显式配置提供，便于其他机器复现。

PDF 保留原件，结构化片段服务检索。命中较小检索单元后，回答模型读取完整条款或表格上下文，降低遗漏例外和脚注的风险。程序核验出处与引文，语义审核检查答案是否真的由证据支持。

## 两条真实决策路径

[最新运行记录](../examples/submission-live.jsonl) 的 normal 用例中，模型检索报销期限，观察到 D01 的期限和逾期说明后直接 finish，并引用原文。

同文件的 missing 用例中，模型先检索育儿假，观察到结果与假期无关，于是换成假期制度相关关键词重搜。仍无有效条款后，返回 insufficient_evidence 和缺口。这一变化由模型根据工具结果选择。

conflict 用例则在观察到 D01 与 D02 的不同期限后报告冲突；replacement 用例获得明确替代公告后按新规则回答。审查时同时看材料、引文和动作，而不只看最终状态。


## 调用流程与决策边界

模型每轮输出一个 JSON 动作，程序执行工具并把结果交回模型。search 一次返回相关原文、同主题候选及明确链接的关联材料。模型可换词重搜、补读、追问或结束。程序验证引用及已启动的主题覆盖，再调用审核模型检查语义。

制度和产品事实使用 basis=evidence，本轮必须检索。conversation 仅用于寒暄、能力说明、范围说明或纯澄清。审核模型会同时检查问题和草稿。路由语义仍依赖模型判断。

| 动作 | 输入和用途 |
|---|---|
| search | query、可选 queries 和 doc_id。检索并读取证据包。 |
| read | 检索候选或已读链接中的片段 ID。读取完整原文或原图。 |
| topic | 已知主题。枚举同主题资料以补充查证。 |
| finish | 回答、引文、缺口、状态和依据类别。经过校验后交付。 |

默认最多 18 个决策回合，可用 --max-steps 调整。达到上限返回 incomplete。工具读取失败最多尝试两次。证据包最多自动读取 24 个片段和 24000 个文本字符，超过预算的条目列入 pending。模型可以继续补读。doc_id 限定首轮候选，主题扩展可能包含其他文档。

## 检索与切片

默认用关键词、中文双字和文档 ID 匹配，标题加权，表格按最佳行匹配。模型可以在同一动作中提供最多三个双语或假设性描述查询。扩展保留问题约束，不得臆造数值。工具合并各路候选，主查询权重 1.0、扩展权重 0.7。实际查询进入 Trace，不进入可引用原文。

启用 --semantic 时，正文按句子和换行组成约 300 字符的检索片段，长句按上限拆分；表格按行和脚注索引。标题附在片段前，命中映射回完整证据。语义查询最多返回 5 个片段，初始余弦阈值 0.5。语义与关键词候选按倒数排名融合。阈值和切片长度需要随语料验证。

假设性描述扩展借鉴 HyDE 思路。默认词法模式使用扩展文本匹配关键词，可选语义模式会将查询编码成向量。项目没有单独验证完整 HyDE 流程的增益。[HyDE 论文](https://aclanthology.org/2023.acl-long.99/)

## 模型接口与部署

问答模型使用 Chat Completions 兼容接口，支持 JSON 动作。读图需要模型支持图像输入。embedding 独立配置为 API 后端或指定本地模型目录，默认运行无需向量依赖。

Embedder 提供 embed(texts) 和可选 query_prefix。API 后端校验数量、索引、数值和维度，归一化后用于检索。本地后端只加载明确指定的目录。local-vector 可选安装组声明依赖，模型权重单独准备。内存索引每次启动建立，适用于当前小语料。

## 引用和冲突

程序检查引文确实来自本轮已读材料，审核模型检查数字、单位、起算点、适用对象和例外。真实引用仍可能被错误解释，因此语义审核结果需要人工抽查。

D01 和 D02 不一致时先检查事项是否相同，再查适用范围与明确替代关系。版本日期本身无法证明优先级。无法判定时引用双方并请求确认。结论限定在已读材料内，区分“可申请”和“必然获批”。

## 附件导入

PDF 和 UTF-8 Markdown 转成带版本的 JSON 证据包，保留原件和必要页面图。PDF 保存页码、正文及表格坐标。简单有框表格提取行列和近邻脚注；无文本页、复杂表格或指定视觉页可返回原页图。人工审核直接核对原件。

跨页合并表格、多栏阅读顺序、无框表格和复杂脚注需人工确认。Tesseract OCR 用于检索转写，视觉结论仍应核对原图。

## 模块与成本

| 模块 | 职责 |
|---|---|
| agent.py、prompts.py | 决策、工具执行、状态和审核 |
| retrieval.py、semantic.py | 关键词、可选向量和证据扩展 |
| embeddings.py、model.py | 可配置的向量与问答模型接口 |
| documents.py、citations.py | 文档表示、定位和引用校验 |
| ingest.py、pdf_import.py、markdown_import.py | 原件留存和导入 |

编排使用 Python 标准库。PDF 用 pdfplumber 0.11.x，原页渲染用 Poppler，可选 OCR 用 Tesseract，PDF 测试样本用 ReportLab 4.x。本地向量适配可选 sentence-transformers 3 至 5。

查询扩展与决策共用一次模型调用。多个不同查询已在同一工具调用执行时，计为完成补搜。模型调用失败返回具体错误类别，当前不自动重试模型请求。成功回答通常还需要一次语义审核调用。

Trace 在每个工具观察中附加当前 step 和 decision，包含动作、参数及模型提供的一句话操作依据；模型调用失败使用当前步的错误记录。离线 DemoModel 明确按预设场景运行，审核也为 Mock。
