# 需求

员工输入制度或产品问题，以及可选对话历史，系统根据带文档 ID 和版本日期的资料给出可核对的答案。当前以合成报销制度为验收语料，提供 CLI、检索和原文读取工具。

制度、产品事实要求本轮先检索。寒暄、能力说明和无法确定查询对象的纯澄清可以直接回复。历史用于解析指代，回答依据来自本轮证据。

输出字段为 answer、citations、gaps、status，可通过 --trace 输出调用过程。引文包含文档 ID、版本和原文片段；PDF 证据可包含页码与位置；图像证据指向原图。状态包括 answered、conflict、needs_clarification、insufficient_evidence 、tool_error 和执行上限触发的 incomplete。

| 验收点 | 成功标准 |
|---|---|
| 明确答案 | 只有 D01 时根据原文回答费用发生后 30 天。 |
| 文档冲突 | D01 为 30 天、D02 为 15 天且关系不明时，引用双方并请求确认。 |
| 资料外问题 | 补搜仍无依据时说明缺口，工具错误与资料缺失分别返回。 |
| 相似问法 | 口语或双语查询能找到相关规则，并保留原文起算点。 |
| 上下文追问 | 理解“超过了”的指代，读取逾期条款。 |
| 工具失败 | 关键证据持续不可读时报告错误，避免给出确定期限。 |
| 替换资料 | 同一问题更换原文后答案改变，明确替代关系要有查证轨迹。 |

错误引文和无依据的确定结论属于关键缺陷。项目交付覆盖小规模语料上的内核、导入和验收。默认关键词检索，可显式配置向量后端。生产权限管理、复杂版面完整识别、大语料召回率和高并发性能尚待验证。

执行记录应包含步骤、工具参数、返回内容及操作依据摘要，至少展示两条由模型根据结果调整的路径。离线 Mock 标注流程验证边界。当前交付提供独立离线入口和真实模型历史记录。
